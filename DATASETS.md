# Полученные данные

Все исходные файлы пользователя скопированы без изменения в `data/raw/` и
проверены по SHA-256. Папка исключена из Git: общий объём около 1 ГБ.

| Файлы | Содержание |
|---|---|
| `calorimeter_response.mat` / `.npy` | Geant4, 10 000 запусков протонов; 809 610 записей энерговыделения, ненулевые попадания у 9 899 событий. |
| `calorimeter_response (2).mat` / `.npy` | Geant4, 10 000 запусков антипротонов; 1 319 688 записей, ненулевые попадания у 9 907 событий. |
| `secondary.mat` / `.npy` | Таблицы вторичных частиц для протонов. |
| `secondary (2).mat` / `.npy` | Таблицы вторичных частиц для антипротонов. |
| `data.zip` | Более ранние архивные наборы моделирования протонов и антипротонов (2023); архив сохранён без распаковки. |
| `sim_info.txt` | Краткое описание столбцов вторичных частиц. |

Числовые массивы в каждой паре `.mat`/`.npy` совпадают. Строки
`last_process` в MATLAB-файлах дополнены пробелами, поэтому побайтового
совпадения форматов нет. Тип первичной частицы проверен по столбцу `ParticlePDG`
в таблицах `secondary`: `2212` для протонов, `-2212` для антипротонов.

`event_ID`, `layer`, `index_along_x`, `index_along_y`, `energy_release`
задают трёхмерные **модельные** попадания на 44 физических слоях.
В антипротонном файле `E_0` содержит 10 000 начальных энергий от 80.487 до
9999.44 МэВ; `layer` принимает все целые значения от 0 до 43. Имя поля
процесса в самих файлах — `last_process` (в переписке оно сокращено до
`last_proc`). Начальные параметры и `Z_end` не подаются на вход обратной
реконструкции.
В адаптере `reconstruction.projections_from_hits` из них создаются только
два доступных измерения: нечётные слои дают XZ, чётные — YZ; пары слоёв
нумеруются от 0 до 21. Координата, не считываемая соответствующей
плоскостью, отбрасывается до оптимизации и не проверяется при отборе
попаданий. Полный список попаданий
используется лишь после реконструкции для приблизительной проверки.

Наборов реальных измерений PAMELA в предоставленных файлах нет.

Новый эксперимент `stars-v1` использует эти же две матрицы как измерения,
но реконструирует их на **44 отдельных физических плоскостях** в
`reconstruction/physical.py` и `physical_fit.py`. `layer // 2` здесь задаёт
только номер строки соответствующей проекции, а не общую глубину двух
соседних плоскостей. Полные попадания на 44 плоскостях используются для
оценки после реконструкции. Автоматическая разметка из `secondary` и
зафиксированное разбиение описаны в `STAR_RECONSTRUCTION_REPORT.md`.
Симулированные попадания на соседних физических плоскостях нельзя считать
точным эталонным вокселем общего слоя: их объединение через `layer // 2`
даёт лишь условную 3D-метрику, которую не следует выдавать за физическую
точность реконструкции.
